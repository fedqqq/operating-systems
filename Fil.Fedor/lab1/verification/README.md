# Результаты проверки

Здесь сохранён фактический вывод команд из Linux-контейнера:

- `tests.txt`: обычная сборка с `-Wall -Wextra -Werror`, C++-проверка singleton
  и 28 интеграционных тестов; все прошли без пропусков.
- `sanitizers.txt`: те же 28 сценариев с AddressSanitizer, LeakSanitizer и
  UndefinedBehaviorSanitizer; все прошли без отчётов об ошибках.
- `demo.txt`: реальный запуск, `/proc` и `ps`, файловые события из отдельного
  журнала rsyslog, SIGHUP, замена процесса и SIGTERM.
- `environment.txt`: ядро Linux, компилятор и версия rsyslog.

Команды воспроизведения приведены в основном README. В ходе проверки
rsyslog использовал рабочее правило из `rsyslog/`, без подмены `syslog`
или inotify тестовыми реализациями. В тесте переполнения демон намеренно
останавливался через SIGSTOP, очередь заполнялась файловыми событиями,
затем проверялись сообщение о потере событий и восстановление наблюдений.

Это результаты указанных сценариев, а не гарантия регистрации операций,
которые inotify объединяет или теряет до установки наблюдений.
